# 0019 报表接口超时（性能热点）

## 背景

`api.daily_report(store, ids)` 给运营后台出「按用户 id 取金额」的报表。数据量上来后接口超时：
线上 10 万行、每次查 2 万个 id，现在要几分钟，SLO 是 1 秒。

小数据量下结果是对的，所以单测一直没红。

## 任务

把 `daily_report` 修到 1 秒内（10 万行、2 万 id），**输出完全不变**：

- 返回 `{id: amount}`；`store` 里不存在的 id 不进结果。
- `api.daily_report` 的签名和返回结构不能变。
- `store.rows` 要保持可读（其它模块依赖它），可以另外加索引。

## 验收

- `pytest` 全绿。
- 原有可见测试的断言不能改。
